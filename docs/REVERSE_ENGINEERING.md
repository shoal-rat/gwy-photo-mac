## 检查、裁切与保存

1. `0x401E90` 检查 JPEG 头；界面文件过滤接受 JPG/JPEG/JPE/JFIF。复现版使用 Pillow 校验实际文件类型与解码情况，比只检查头更严格。
2. `0x4013A0` 读取 `[PhotoInfo]` 并检查源图最小宽高。
3. `0x401070` 取得三处 3×3 区域的 RGB 均值：`(width/10, height/10)`、`(width/10, height/4)`、`(width-width/10, height/6)`，整除向零取整。RGB 归一化后换算 HSI。
4. `0x401000` 先要求 `I >= i_min`。`I >= i_max` 且 `S <= s_min` 归为白底；否则在蓝色色相范围内且 `S >= s_max` 归为蓝底；其余拒绝。三处类别须一致。原程序的色相绕回常数为 `6.28318`，本项目保留该值。灰阶的色相分母为零时，本项目使用零色相，白底分支不依赖色相。
5. 使用 `haarcascade_frontalface_alt2.xml`、灰度输入、`scaleFactor=1.1`、`minNeighbors=2`、`flags=1`、最小人脸 `30×30`。多个检测结果时 `0x401932` 取宽度最大的框，不因数量大于一直接拒绝。
6. `0x40196A` 要求人脸框宽度/源图宽度至少 `0.32`。裁切宽度为 `int(face_width × 1.6181229773462784)`，高度为 `int(crop_width × dst_height / dst_width + 0.5)`。围绕人脸框居中后夹到源图范围。
7. `0x401A3E` 计算 `(crop_height × dst_width) / (crop_width × dst_height)`。小于 `0.9` 时收窄，大于 `1.1` 时收短；再检查人脸左、右和顶部边距比例。除法取整采用 C/C++ 向零截断，而非 Python 负数地板除。
8. `0x401BB6` 设置 ROI，以 `cvResize(..., 1)`（双线性）输出目标大小。不是超分辨率或人像生成。
9. `0x40310E–0x40311B` 传入单精度 `40.0`，再由 `0x401F10` 调用 CxImage 设置 JPEG 质量并重编码。本项目使用 Pillow 质量 40、常规 4:2:0、非渐进 JPEG；无法保证量化、DCT、元数据、色度处理与原 CxImage 完全一致。
10. `0x401E10–0x401E88` 以 `rb+` 打开文件，定位末尾，附加十字节：

    ```text
    FF 02 00 08 67 6A 67 77 79 32
                g  j  g  w  y  2
    ```

    信息位于 JPEG EOI `FF D9` 后。这是观察到的静态尾部格式，不是数字签名；不能据此推断服务端仅检查这些字节，不能宣称拥有官方审核结果。

## 配置默认值

| 键 | EXE 内置默认值 | 参考分发包 photo.ini |
| --- | --- | --- |
| min_width / min_height | 295 / 413 | 未覆盖 |
| dst_width / dst_height | 295 / 413 | 未覆盖 |
| ratio_x_min / ratio_x_max | 0.0 / 0.5 | 未覆盖 |
| ratio_y_min / ratio_y_max | 0.0 / 0.5 | 未覆盖 |
| blue_h_min / blue_h_max | 2.5 / 4.5，弧度 | 未覆盖 |
| red_h_min / red_h_max | 0.0 / 5.0 | 未覆盖；已识别分支不使用红色色相范围 |
| i_min / i_max | 0.1 / 0.9 | **0.1 / 0.7** |
| s_min / s_max | 0.05 / 0.3 | **0.05 / 0.1** |

不指定配置时，本项目使用参考包的 INI。显式指定配置时，缺失项回退到 EXE 内置值；不是合并到参考 INI。复现版对非有限数字、无效范围、非正尺寸等异常配置给出错误；旧 API 对异常字符串的宽松转换行为没有复刻。

## 确认过的部分与未确认部分

- 原 EXE 的背景类别函数可在不调用任何 Windows API 的条件下执行。可选脚本把正常值和边界值送入该机器码，与 Python 实现比较。
- 裁切片段通过模拟 `_ftol` 的向零截断，对不同图像/人脸框比较裁切结果和成功/失败分支。
- 测试覆盖文件格式、像素不足、背景类别/边界、无人脸、比例、标记、JPEG 解码、覆盖保护、CLI 和界面状态。公开测试不包含个人证件照。
- 本地实现曾用一张用户授权的证件照验证完整检测和输出；照片、文件名、路径、报告和预览未收入仓库。
- **未完成完整 Windows 应用在同一输入集合上的逐字节或逐像素对比，未验证所有输入类型，也未在报名网站验证上传。**

## 已知差异

| 部分 | 差异与影响 |
| --- | --- |
| 解码 | Pillow 与 OpenCV 1.0 的 JPEG/色彩解码可能不同；本项目应用 EXIF 方向，并移除输出 EXIF |
| 检测 | 保留同一 XML 与调用参数，运行库换为 OpenCV 4.11；检测框和边缘病例可能不同 |
| 编码 | 使用 Pillow 而非 CxImage；相同“质量40”不保证相同字节或文件大小 |
| 灰阶/异常数值 | 对无定义色相、坏配置、损坏文件作明确处理，避免复制崩溃或未定义行为 |
| 界面 | 复现操作流程和错误类别，不使用原版位图，不逐像素复制 Windows 窗口 |
| PNG | 只有使用者显式开启才转换；原版严格路径不接受 PNG |
| 原图保护 | 保存时拒绝同路径、软链接或硬链接覆盖源图 |
